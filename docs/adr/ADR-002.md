# ADR-002: Phase 2 Recall Mode Engine and CI Security Mitigations

**Status**: Accepted  
**Date**: 2026-04-12  
**Project**: omoide — local encrypted secret manager  
**Author**: Inigo  

---

## Context

Following the completion of Phase 1 (Core Crypto Primitives and Vault Format), `omoide` is proceeding with Phase 2: the "Recall Mode" engine. The core philosophy of `omoide` relies on cognitive-cryptography-driven authentication, where the Master Password must be consistently rehearsed to prevent memory degradation, eliminating the risk of catastrophic forgetting while maintaining maximum security.

Additionally, during continuous integration (CI) tests, a security advisory error surfaced indicating that `rand` crate version `0.8` possessed unsound behavior. Given the threat model of the system, this vulnerability must be mitigated immediately alongside the feature updates.

---

## Decisions

### 1. Spaced Repetition System (SRS) Integration

**Decision**: Integrate an SRS state directly into the vault structure to enforce Master Password "Emergency Access Rehearsals." 

**Rationale**:
- **Vault Binding**: `SrsState` is now structurally bundled within the `VaultHeader`, tying the rehearsal schedule to the vault instance itself.
- **Algorithm Parameters**: The default interval is set at 12 hours. Successful unlocks multiply the interval by 1.5, while failures penalize by dividing it by 2.0. This exponential curve efficiently forces early practice and gently tapers off as cognitive memory hardens. 
- **Time Representation**: Rehearsal times use Unix timestamp seconds (`u64`) to minimize platform-specific parsing complexities. Interval and due date algorithms are isolated within `omoide-core/src/srs.rs`. 

### 2. Vault Schema Version Migration

**Decision**: Increment the `VAULT_VERSION` from `1` to `2`. 

**Rationale**: 
- The addition of `SrsState` in `VaultHeader` (`omoide-format`) modifies the underlying CBOR serialization layout.
- `omoide-env` reflects this change by updating the global `VAULT_VERSION` constant, acknowledging that legacy `v1` implementations are incompatible with the SRS framework without a dedicated migration step.

### 3. Master Password "Anchor Memory" Wizard

**Decision**: Introduce an interactive "Password Architect Wizard" natively into `omoide-cli`.

**Rationale**:
- Providing a standard CLI pathway to scaffold Master Passwords utilizing a "Nonsense Logic" mnemonic PAO schema (Place + Action + Object, e.g., `AtticSprintingViolin`) directly improves user experience to the strict recall requirements of the SRS. 

### 4. Upgrade `rand` Dependency

**Decision**: Upgrade the `rand` crate workspace dependency from `0.8` to `0.10.0-rc.9`.

**Rationale**:
- A CI security job uncovered an unsoundness vulnerability in the `0.8` version. Upgrading to the `0.10.0-rc.9` release candidate immediately mitigates the vulnerability within the `omoide` threat model, allowing security pipelines to pass.

### 5. Migrate from `OsRng` to `SysRng`

**Decision**: Replace the invocation of `OsRng.fill_bytes()` with `SysRng.try_fill_bytes()` via the `TryRng` trait.

**Rationale**:
- Following the update to `rand 0.10`, the recommended OS randomness generator transitioned to `SysRng`. 
- During the implementation, attempting to conventionally use `.fill_bytes()` generated a compile-time error. This happened because in `rand 0.10`, `SysRng` does not implement the infallible `RngCore` trait, recognizing that OS entropy sources can fail.
- Instead, `SysRng` relies on the `TryRng` trait. Shifting to `try_fill_bytes` safely resolves the error by enforcing explicit OS failure control. In the event of system entropy exhaustion, the app unpacks the `Result` and prints a deterministic error string (`"CRITICAL: OS failed to provide secure randomness."`), matching modern Rust safety profiles.

---

## Consequences

- The vault file format is substantially modified to persist SRS intervals. Any subsequent features tracking further rehearsal metadata will necessitate a subsequent version format bump.
- The User Experience changes: users must now practice typing their Master Password on a schedule. If they fail or miss rehearsals, they will be forced to practice more often.
- CI pipeline blocking related to `cargo deny` dependency tracking has been resolved, asserting that primitive security generators remain structurally sound.
